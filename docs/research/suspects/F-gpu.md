# Area F: the GPU's own work (what the RTX runs)

Static analysis only (no build, no run). Read: `engine/docs/perf-audit.md` (TICK-015/016/019/020/033/053/057), `docs/benchmarks/2026-11-12-tick057.md`,
`docs/research/occlusion.md`, `replay-cost.md`, and the code of `vk_main.cpp`, `vk_draw.cpp`, `vk_texture.cpp`, `vk_replay.cpp`, `vk_shader.cpp`,
`eden/shader_recompiler/backend/spirv/*`. Guest programs are named by key only. "measured" = a figure in the cited file; "estimated" = mine.

## What the GPU frame is made of (measured)
- Main PC (RTX 5070): busy ~10.8 ms of ~15 ms (perf-audit TICK-020, under nsys): replay submissions 6.12 + one long submission 3.20 + small 1.07 + empty 0.53.
  In-engine split (PASS_TIMING, inflated): passes 5.06, dispatches 1.82, msync 1.30, wb 0.43, rbrefresh 0.43, barriers 0.58. The GPU is **not** the limit on the
  main PC; it matters through the tail before the capture drain (chain B: the GPU must finish before the late-page wait ends) and through idle bubbles.
- PC 3050 (2560x1440): recordings 19.4 ms + uploads 2.6 ms, ~15 ms with no gap before each late wait ends (TICK-057). Passes 12.4, dispatches 4.5, barriers 1.1.
- ~150-200 render passes and ~130-157 dispatches a frame (TICK-016 log: 1710 draws, 157 dispatches, 152 passes; replay-cost: 3040 draws, 199 passes, 550 full
  barriers recorded). Each pass/dispatch is short (0.07-0.2 ms), so every full-GPU drain between them costs a ramp-down and ramp-up.
- Strongest single GPU number in the repo: `RX_VK_TEST_BARRIER_DROP=1` on 3050: gpu_ms 19.9 -> 16.8 (-3.1), late wait -2.6, fps 28.95 -> 31.47 (tick057 s57d).

## Already tried or checked (not re-proposed)
Render target formats (TICK-016); load/store ops "LOAD/STORE in GENERAL" on an immediate-mode GPU (TICK-016); clears (1 a frame); pass/dispatch trust barriers,
BARRIER_DEDUPE_PAR, GAME_BARRIER_NARROW (a narrower *destination* drains the same on this driver), MIRROR_STICKY/VRAM_FREE/KEEP, RB_RANGES, LATE_MERGE, the
mirror-sync compute copy (TICK-021), the wb diff (TICK-048), occlusion queries (off by default; real counts cost more than they save), GPL fast link (off),
overlay and menu (`menu_record` returns before any pass when nothing shows), upscale/sharpness (`framegen_scale` returns at once with both off), the subgroup
pin to 32, sampler anisotropy (mirrors the game). `RX_VK_ROBUST=0` was run once, on 3050 only (29.93 vs 29.5 fps, gpu_ms 19.1 vs 19.5: inside the spread).

## Notes on the top 5

**F1, barrier elision by hazard tracking.** TICK-057 shows that engine-side GPU cuts of copies and barrier *repeats* did nothing, while dropping the pass-start,
dispatch and game barriers cut gpu_ms by 3.1 ms. So the lever is not duplicate barriers but barriers that look needed and are not. The engine already tracks per-pass
`written`, `sampled_targets` and per-texture written marks (`draw_hazards`, `texture_written`). A conservative scheme: a barrier is needed only if the next pass or
dispatch samples/reads a texture or buffer written since the last barrier, writes one read or written since, or its program follows pointers or writes storage
(unknown aliasing). Hard parts: guest memory aliasing (pools, mirrors), pointer-following shaders, and the game's own ORDER_PRIMITIVES (0x11) barriers, which are real
ordering. Start with a measure-only mode that logs how many barriers would be skippable, by kind; the TICK-016/057 "trust" switches skipped far fewer (8 of 74 pass
starts, dispatch barriers only after draws) and were inert in parallel segments, so their effect on the main PC was never separated from noise.

**F2, inert proxy draws.** The report values are fabricated (4096) in the default mode, so the ~900 proxy test draws at the start of each frame cannot influence the
picture unless they write colour, depth, stencil or storage. A draw filter in `draw()`: all colour write masks 0 && no depth/stencil write && fragment stage has no
stores/atomics && `OCC_REAL==0`. It saves their record cost on the segment workers (chain B, though the replay-CPU agent may also list it) and the raster of ~900
boxes. Check that a skipped draw does not call `begin_pass` for other targets and that `texture_written` marks are only set for draws that write.

**F3, NonWritable/NonReadable.** The flag data exists; the emitter ignores it. The risk is only the correctness of `is_written` for the global-memory-to-SSBO pass
(merged descriptors, `Info::global_tables`, `RX_VK_FOLLOW_STORES` off by default, atomics through `needs_function`). Start with images and plain SSBOs whose
descriptor is not written, in programs with no atomics. Output should be bit-identical.

**F4, scoped robustness.** Robust buffer access was turned on globally to stop faults in two culling programs and garbage lighting reads; TICK-016 never A/B'd it and
TICK-057 saw +0.4 fps and -0.4 gpu_ms on 3050. With `VK_EXT_pipeline_robustness` only the programs that need it would pay. It needs a bisect of which programs need it, hence
effort M and picture risk until done. The first step costs nothing: the main-PC A/B of `RX_VK_ROBUST=0` with pass timing, which was never run.

**F5, indirect mesh conversion.** Each converted draw is a pass break and three global drains, so the cost scales with the number of GPU-built mesh draws, which no log
reports. Add the counter first. A form that keeps the picture identical: convert all record buffers once, outside any pass, right after the culling compute that wrote
them (or in one dispatch writing the {count,1,1} triplets), so the render pass stays open across the mesh draws.

## Honest negatives
- No evidence that texture formats, MSAA resolves, sampler setup, depth handling, pipeline flags (GPL off, no DISABLE_OPTIMIZATION in play), overlay/menu or upscaler passes cost anything per frame when off.
- ASTC->BC7 transcoding (0.47-0.65 ms profiled on 3050) happens at texture creation (load/streaming), not in steady state.
- The game's own passes at 2048x1152 / 2560x1440 and its networks are its own work; the quality constraint rules out touching them.
