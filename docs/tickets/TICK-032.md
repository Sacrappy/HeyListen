# TICK-032 — Why real occlusion breaks rendering (research)  · model: Opus · read-only
**Why**: enabling real occlusion queries gives permanently white/missing meshes and a washed-out picture (TICK-027 runs); known and unsolved in Hookshot and Lichii (user). "Occlusion Off" makes the game draw every candidate (+~29% draws in oot-pc's measurement).
**Goal**: research only (no game runs): read Hookshot's docs/code/issues/commits on occlusion (engine/nx2/oot_occlusion.py, engine/docs/*, `gh issue list -R NotRexed/Hookshot --search occlusion`, commit messages), Lichii's NX2_NOTES.md / NX2_GPU_THREAD_SPLIT.md and code (E:\OOT\Lichii-1, query/report/conditional-render handling in video_core), NX2navi's design notes (E:\OOT\references\NX2navi docs/maxwell.md, docs/architecture.md; ideas only for post-0478c13 content), TICK-027's experiment (its branch feature/TICK-027-occlusion and perf-audit section). Determine the mechanism: what the game does with the counts (does it skip drawing, skip updating, or use them for something else — lens flare / sun visibility / exposure?), why real counts lead to white/missing meshes (counts read too early, wrong units — samples vs boolean, conditional rendering semantics, reports written to the wrong place, a one-frame latency the game does not tolerate, query reset races), and what a correct implementation needs.
**Deliverable**: docs/research/occlusion.md with evidence (file:line, issue/commit links), a ranked list of hypotheses with how to test each cheaply, and a recommended design.
**Branch**: `feature/TICK-032-occlusion-research` (docs only)
