# TICK-027 — Real occlusion queries  · model: Opus · after TICK-026
**Why**: the engine answers every occlusion query "visible" (Occlusion Off, engine/nx2/oot_occlusion.py), so the game draws every candidate. oot-pc measured ~29% fewer draws with real counts; Castle Town has ~3,500 draws a frame. Design reference (MIT, usable with a THIRD_PARTY_NOTICES row): NX2navi base import `git -C E:/OOT/references/NX2navi show 0478c13:runtime/vk_exec_xfer.c`, section "occlusion counts": a ring of 4096 Vulkan occlusion queries with host reset, results summed by the completion thread, a result not ready counts as visible, conditional rendering evaluated on the CPU against a pending-report table (64K slots; reports pending until the completion thread has written guest memory, not just until the fence passes). See docs/references/NX2navi.md.
**Goal**: real occlusion counts with one frame of latency, safe defaults (not ready = visible), the game's occlusion reads re-enabled; measure draws, replay CPU, GPU time, and the game's own CPU (does it skip work for occluded objects?).
**Acceptance**: draws a frame down at Castle Town and Hyrule Field; fps / 1% low up; no popping or flashes (flash detector, screenshots while walking/turning); game speed ok.
**Branch**: `feature/TICK-027-occlusion`
