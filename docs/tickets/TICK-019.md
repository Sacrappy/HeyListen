# TICK-019 — GPU reads of imported host memory  · model: Opus
**Why**: TICK-017: when CPU and GPU overlap, the GPU gets slower (89% busy, ~16 ms busy a frame at 56 fps; the 2048x1152 pass 4f0c0b40 rises 0.82 -> 1.34 ms) and ~5 ms of GPU-busy time a frame is in no timed command buffer. The engine imports ~1.4-1.8 GB of guest (host RAM) memory into Vulkan (log: "imports: N live (X MB)"); whatever the GPU reads from there crosses PCIe and contends with CPU writes. Even serialised, this may be a large hidden share of the ~9.8 ms GPU frame.
**Goal**: measure what the GPU reads straight from imported host memory each frame (by pool/usage: vertex, index, uniform, storage, textures, indirect), its cost (A/B: forcing mirrors on for those pools; timestamps; Nsight if available), and serve the hot ones from device-local mirrors (TICK-015's pool-flags machinery shows which pools are CPU-written; mirrors already exist for some). Then re-try TICK-017's deferral (RX_VK_CAPTURE_DEFER=1 / SLACK) on top.
**Acceptance**: GPU ms a frame down and fps up at limit 120 in Hyrule Field; picture correct (screenshots, flash detector); game speed 100%; VRAM use reported.
**Branch**: `feature/TICK-019-host-imports`
