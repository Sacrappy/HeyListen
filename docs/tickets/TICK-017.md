# TICK-017 — Overlap CPU and GPU: break the once-a-frame serialisation  · model: Opus
**Why**: at ~74 fps (13.5 ms a frame) the GPU has ~9.8 ms of work (TICK-016) and is ~77% busy; the main thread waits 2.3-5.5 ms a frame for the GPU in the exposure-meter capture wait (TICK-010/015), so CPU and GPU take turns instead of overlapping. Removing the wait outright was slower (TICK-010: the game falls back to its own nvnSyncWait and 1 ms sleeps when the CPU runs ahead).
**Goal**: let frame N+1's CPU work overlap frame N's GPU work while keeping the game's view of GPU results consistent: e.g. serve the exposure meter (and other GPU->CPU readbacks the capture waits for) from the previous completed frame (one frame of latency, as on hardware double buffering), restrict the wait to the pages actually read, or move the wait off the main thread to the point the game really consumes the value. Find which guest reads require the wait (read traps / readback page set).
**Acceptance**: GPU busy share up (nvidia-smi > 90%) and fps up at limit 120 in Hyrule Field; no exposure flashes / wrong lighting (flash detector, screenshots); game speed 100%.
**Branch**: `feature/TICK-017-cpu-gpu-overlap`
