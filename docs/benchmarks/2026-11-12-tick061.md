# TICK-061: chain B (the held flush and the Presentation Thread's replay), switch by switch (2026-11-12)

## Setup
- Ryzen 7 7800X3D, RTX 5070, Windows 11; Market save; `run_bench.py` 110 s, `--warmup-s 66`, `--fps-limit 360`, frame generation
  off, windowed. Harness in the worktree's `build/tick061` (not in git): `run.py` (one run; saves compared with the backup and no
  game left after every run), `ab.py` (interleaved screen, one binary, variants as environment; it also keeps the log's capture,
  take and dry-pass lines and, when a `HOS_JOBTRACE` window was taken, `chainb.py`'s loop), `summ.py`, `speed.py`.
- Binary: `bin/v3` (branch 79da345: every TICK-061 switch, all off). Base = no environment = main 9bfc390's behaviour.
- fps / 1% low / p99 ms; frame prep = the Presentation Thread's replay time a frame (the log's `submit`, ms). Log metrics are means
  of the last windows of each run: "cap" = a submit's capture (all, scan, copy; ms, all six submits a frame averaged), "take" = a
  capture taken (all ms), "parts" = inside the take (page stamps / texture shadow / table entries, ms a take), "dry" = a parallel
  command buffer's dry pass (ms).

## A start that rebuilt the program cache (fixed before any measurement)
The first build (v2) added a field to `Program` (vk_shader.h) for F2. `sizeof(Program)` is part of the program cache's stamp
(vk_shader.cpp `disk_stamp`), so the first run found "0 program keys kept", truncated `hookshot_programs.bin` and spent its 110 s
translating (0 frames measured). Fixed in 79da345 (F2's answer kept by program key and variant in vk_draw.cpp, not in Program; no
stamp input differs from main). The shared cache was rebuilt at once for the game folder's own build (TICK-054's exe b6462ab3 /
dll 07b8dcd6) with `HeyListen.exe --prepare-shaders` under the lock (2.5 min), so the other tickets' builds find it as before.
